03 头文件与延时函数逐行讲解

第 1 行 · 包含 8051 寄存器定义

#include <reg51.h>
它是什么，是什么意思
这是预处理指令，编译前读取 reg51.h 中的硬件定义，使编译器认识 P1、P3 等端口名称。
关键词与符号
#include 是包含头文件指令；<reg51.h> 是工具链提供的经典 8051 头文件名。这里的 < > 界定文件名，不作大小比较，该行不需要分号。
执行时单片机做什么
这行在编译前起作用；运行时单片机不会再执行一次“读取头文件”的动作。
为什么需要
P1、P3 不是普通 C 自带的变量，需要头文件提供与硬件对应的定义。
删除或改错会怎样
若删除且没有另外定义这些寄存器，后面的 P1、P3 会未定义，不能正常编译。
通俗理解
先告诉编译器：这些端口名对应哪些 8051 硬件。
课堂简答
这行包含 8051 的寄存器定义，让编译器认识 P1、P3 等硬件端口。

老师可能问：reg51.h 在这里有什么作用？

第 3 行 · 把 P3.3 命名为 key

sbit key = P3^3;
它是什么，是什么意思
这是 C51 特殊位声明，给 P3 寄存器的第 3 位起名 key，用它读写 P3.3。
关键词与符号
sbit 是特殊位定义关键字；key 是自选名字；P3 是端口寄存器；在这个声明里 ^3 指定第 3 位。位号从 0 开始，P3.3 是端口的第四个位。这里 ^ 不是乘方或普通异或计算。
执行时单片机做什么
编译时建立引脚映射，没有另建一个保存输入副本的独立变量，也没有立即将该引脚置高。
为什么需要
让后面的输入判断写成 key == 0 或 key == 1，直观地只操作 P3.3。
删除或改错会怎样
key 没有定义会报错；若改成 P3^2，则程序读 P3.2，和原接线不匹配。
通俗理解
给 P3.3 这个引脚贴上 key 的名字。
课堂简答
这行用 sbit 将 P3.3 命名为 key。^3 指 P3 的第 3 位，后面通过 key 检测开关电平。

老师可能问：P3^3 中的 ^3 是什么意思？

第 7 行 · 定义带参数的软件延时函数

void mDelay(unsigned char Delay)
它是什么，是什么意思
定义名为 mDelay 的函数，接收一个 unsigned char 类型的参数 Delay；函数体在第 8～15 行。调用 mDelay(20) 时，这次调用的 Delay 初值为 20。
关键词与符号
函数前的 void 表示不返回数值；unsigned char 表示参数为 8 位无符号整数，0～255；Delay 是参数名。大小写有区别，mDelay 是函数名，Delay 是次数变量。
执行时单片机做什么
调用时进入函数，接收传入的次数，执行循环后返回调用位置的下一可执行语句。每次新调用都会重新获得传入的参数值。
为什么需要
让三处消抖都调用同一个函数，用参数指定外层轮数，避免重复写延时循环。
删除或改错会怎样
删除函数会使调用无对应定义；删掉参数类型则不能清楚地声明参数接口。参数无需在函数外再声明一个同名全局变量。
通俗理解
把“循环等多少轮”交给调用时填入的数字。
课堂简答
这行定义无返回值的延时函数，参数 Delay 用来控制外层循环次数。mDelay(20) 就把 20 传给它，但不自动保证是 20ms。

老师可能问：void 和 unsigned char Delay 分别表示什么？

第 9 行 · 声明内层循环变量 i

unsigned int i;
它是什么，是什么意思
在延时函数内声明局部变量 i，供内层循环计数使用。它不是脉冲计数变量 count。
关键词与符号
unsigned int 在 Keil C51 中是 16 位无符号整数，范围 0～65535；unsigned char 是 8 位，范围 0～255。本行没有赋初值，i 的初值在第 13 行设置。
执行时单片机做什么
确定 i 的类型和存储；本行自身不产生确定次数的延时，后面的循环才消耗执行时间。
为什么需要
给内层循环提供计数变量。当前最终代码没有 volatile，空循环是否保留与编译优化有关，需要固定优化设置并测量。
删除或改错会怎样
删除整行会使 i 未定义。不能认为声明了一个变量就已经完成了软件延时。
通俗理解
准备一个变量，数内层循环做了多少次。
课堂简答
这行声明 16 位无符号循环变量 i，后面的 for 用它从 0 数到 110。它和记录脉冲次数的 count 不同。

老师可能问：unsigned int i 是多少位，范围是多少？

第 11 行 · 外层 for 按参数次数重复

for (; Delay > 0; Delay--)
它是什么，是什么意思
先检查 Delay > 0；成立就执行第 12～14 行的一轮内层循环。该轮完成后执行 Delay--，再检查条件。
关键词与符号
for 的括号内用两个分号分成“初始化；条件；更新”。第一个位置为空，因为 Delay 已从调用参数取得初值；> 表示大于；Delay-- 是减 1。条件后没有终止循环体的额外分号，后面的 { } 才是循环体。
执行时单片机做什么
mDelay(20) 时，Delay 从 20 到 19、18……到 0，共执行 20 轮。每一轮内层结束后才减一次 Delay。
为什么需要
把多轮小循环组合为一次更长的软件等待，并让不同参数值可以控制轮数。
删除或改错会怎样
去掉 Delay-- 会在传入正数时不断循环；若错误地在整个 for 括号后加分号，真正内层块就不会被这个外层循环重复执行。
通俗理解
还剩几轮就再做一轮，做完减一轮。
课堂简答
这是外层延时循环。Delay 已由参数赋值，所以初始化部分留空；每完成一轮内层，Delay 减 1，变成 0 就结束。

老师可能问：for 的三个部分分别做什么？

第 13 行 · 内层空循环与末尾分号

for (i = 0; i < 110; i++);
它是什么，是什么意思
每轮外层开始时，把 i 设为 0；只要 i < 110 就继续，每轮 i 加 1。末尾分号表示循环体是空语句，没有另外的业务动作。
关键词与符号
i=0 是初始化；i<110 是继续条件；i++ 是更新。i 的值依次为 0～109 进入循环，更新到 110 后停止，所以执行 110 次，不是 111 次。最后的 ; 在这里有意作为空循环体。
执行时单片机做什么
在循环保留的编译结果中，CPU 反复判断并更新 i，这些操作消耗时间。下一轮外层又会重新执行 i=0。
为什么需要
用重复执行操作来形成普通软件延时。110 是当前代码的循环上限，不是已经测得的 1ms 时间常数。
删除或改错会怎样
删除整个内层会大幅缩短等待；直接删末尾分号而不提供其他循环体会破坏语法。优化也可能缩短或删除空循环，需实际检查。
通俗理解
每一大轮，都从 0 重新数 110 次小循环。
课堂简答
这个 for 让 i 从 0 增加到 110，执行 110 次。末尾分号是空循环体，循环判断和自增用于消耗 CPU 时间。

老师可能问：这个 for 最后为什么有分号？

一次 mDelay(20) 怎样执行

  1. 调用把数值 20 交给参数 Delay。
  2. 第 11 行检查 Delay>0，成立就执行内层。
  3. 第 13 行将 i=0；i 为 0～109 时执行空循环，并在每轮结束 i++；i=110 时退出。
  4. 完成一整轮内层后执行 Delay--，从 20 变成 19；再从第 11 行检查下一轮。
  5. 共 20 轮，每轮 110 次内层循环，总计 2200 次内层循环。Delay 为 0 时函数返回。
  6. 下次再调用 mDelay(20)，该次调用重新收到 20，不会沿用上次减完的 0。

次数可以从源码数出来，毫秒不能只靠名字或参数认定。实际执行时间取决于循环是否保留、每轮生成多少操作以及 CPU 时钟。尤其 unsigned int 是 C51 的 16 位类型，不能照搬某个 8 位循环的时间常数。

04 主函数与启动等待逐行讲解

第 19 行 · 进入主函数

void main(void)
它是什么，是什么意思
这是主函数的定义开头。C 运行环境完成启动后进入 main，第 20～49 行构成主函数体。
关键词与符号
main 是入口名称；前面的 void 表示不返回数值，括号中的 void 表示没有参数。这里采用 Keil C51 的嵌入式写法。
执行时单片机做什么
进入 main 后先定义 count、设置输入与显示，再完成一次启动等待，最后进入无限循环。
为什么需要
提供实验程序的入口，组织初始化和持续检测。
删除或改错会怎样
没有有效的 main 入口，不能正常链接和执行本实验逻辑。
通俗理解
单片机启动后，从这里开始做实验。
课堂简答
main 是主函数，系统启动后从这里执行初始化，再进入持续检测开关的循环。

老师可能问：void main(void) 中两个 void 表示什么？

第 21 行 · 清零 8 位脉冲计数变量

unsigned char count = 0;
它是什么，是什么意思
定义 count 并初始化为 0，用它记录已确认完成的脉冲次数的低 8 位。
关键词与符号
unsigned char 在 C51 中为 8 位无符号整数，范围 0～255；count 是变量名；=0 是初始化。char 在这里存数字，不是只能存字符。
执行时单片机做什么
count 初值成为 0；这句在主循环外，仅在进入 main 时初始化一次。之后每次确认动作通过，第 43 行加 1。
为什么需要
使第一次显示从 0 开始，并用八个位匹配八个 LED。
删除或改错会怎样
删除变量声明会未定义；删初值会失去明确的初始计数。若把清零放在每轮无限循环内，就不能持续累计。
通俗理解
准备一个从 0 开始、到 255 后回零的小计数器。
课堂简答
这行定义 8 位无符号计数变量 count，初值为 0。范围是 0～255，255 再加 1 存回该变量时变成 0。

老师可能问：count 为什么用 unsigned char？

第 23 行 · 为准双向输入口先写 1

key = 1;
它是什么，是什么意思
向 P3.3 的端口锁存位写 1，解除该位主动输出低电平的状态，让外部开关能够决定读入的电平。
关键词与符号
key 是 P3.3 的别名；= 是赋值或端口写操作；1 表示将对应锁存位置 1，不是比较输入当前是否为高。
执行时单片机做什么
写 1 后内部上拉使开关断开时通常为高，开关闭合接地仍能把实际引脚拉低。它不是命令外部信号永远为 1。
为什么需要
准双向口如果锁存位为 0，会由端口自身主动拉低，无法可靠读到开关断开后的高电平。
删除或改错会怎样
复位后端口通常已经为 1，但不能一直依赖这种碰巧的初始条件；若锁存位曾为 0，输入检测可能一直读低。
通俗理解
先让引脚解除主动拉低，再读取开关的高低。
课堂简答
P3 是准双向口，用作输入前先写 1，解除主动输出低电平，让外部开关控制实际输入电平。开关闭合时仍能读到 0。

老师可能问：写了 key=1，为什么还能够读到 0？

第 24 行 · 把初始 0 转为八灯全灭的输出

P1 = ~count;
它是什么，是什么意思
将 count 按位取反后的低 8 位写入 P1。count=0 时，P1 得到 0xFF，八个位为 1，因此低电平点亮的八灯全灭。
关键词与符号
P1 是八位硬件端口寄存器，控制 P1.0～P1.7；~ 是按位取反；= 是输出赋值。count 参与表达式可能先整数提升，但写入八位 P1 时只保留低 8 位。
执行时单片机做什么
一次更新八个位的输出锁存状态，设置与 count=0 对应的初始显示。取反不会改变 count 本身。
为什么需要
逻辑计数位为 1 要亮灯，而实验仪输入 0 才亮，所以输出必须反相；count=0 应显示全灭。
删除或改错会怎样
删除会依赖端口以前的状态。去掉 ~，count=0 时 P1=0，八个低有效 LED 全亮，显示与目标相反。
通俗理解
要显示数字 0，就给八个低有效灯输出八个 1。
课堂简答
这行把 count 取反送到 P1。初值 count=0，输出 0xFF，所以八个低电平点亮的 LED 全灭。

老师可能问：为什么 count=0，P1 却输出全 1？

第 26 行 · 启动时等待已有低电平结束

while (key == 0);
它是什么，是什么意思
如果启动时 key 为 0，就反复等待；读到 1 后退出。它位于 while(1) 外面，启动时只执行这一段一次。
关键词与符号
while 重复检查条件；==0 表示输入是低；末尾的 ; 是循环体为空的空语句。它不是普通赋值末尾的分号，也不是等待固定 20ms。
执行时单片机做什么
CPU 反复读 P3.3，期间不修改 count。上电时开关已接通，则先等待断开，忽略这段已有低电平。
为什么需要
避免从启动时已经存在的接通中途开始，把这段旧低电平直接算成新操作。
删除或改错会怎样
删除后，如果上电已经为低，后面的主循环可能直接接受这段低电平并在释放时计数，没有明确的高起点。
通俗理解
上电时如果已经接通，先等它断开再开始。
课堂简答
这句在启动时等待输入从低恢复高。分号表示空循环，输入还低就一直等，防止把上电前已有的接通算作新动作。

老师可能问：这条 while 后面的分号是什么意思？

第 27 行 · 启动等待后延时一次

mDelay(20);
它是什么，是什么意思
第 26 行读到高并退出后，调用 mDelay，传入 20，让它执行 20 轮内层循环。这一调用在主循环外，启动时执行一次。
关键词与符号
mDelay 是函数名；(20) 是把整数 20 传给参数 Delay；; 结束调用语句。函数定义在前面，主函数可直接调用。
执行时单片机做什么
CPU 进入第 7～15 行，执行完返回到无限循环。20 是轮数，真实时间由循环、编译结果和 CPU 时钟决定。
为什么需要
在初始等待结束后留出一段时间，让输入有机会趋于稳定。该代码没有在延时后另加初始高电平 if 复查，不能说它证明了稳定高持续 20ms。
删除或改错会怎样
删除后会立即进入主循环，初始信号缺少这段等待，可能更受刚释放时抖动的影响。
通俗理解
先等到断开，再稍等一会儿，然后开始循环检测。
课堂简答
这句在启动等待结束后调用延时，20 控制外层轮数，让初始状态有时间稳定。它只在进入主循环前执行一次。

老师可能问：mDelay(20) 的 20 是循环次数还是自动保证 20ms？

哪些内容只做一次

第 21 行清零、第 23 行输入准备、第 24 行初始显示、第 26 行初始等待以及第 27 行初始延时，都在第 29 行无限循环外。只在进入 main 时完成一次，不是每一个脉冲都再执行。

初始等高后的延时没有紧接一个初始高电平复查 if。因此准确说法是“等初始低结束并延时，让它有时间稳定”，不能说程序证明了此阶段一直稳定高 20ms。后续每轮只从第 31 行继续检测。

变量与端口不要混淆

count=0 是内部数字；P1=0xFF 是显示这个数字所需的硬件电平；key=1 是输入口的锁存准备。它们分别作用于计数变量、输出端口和输入端口。

第 39 行 · 对第一次回高延时消抖

它是什么，是什么意思
第 37 行第一次读到高以后，调用 mDelay(20)，再由第 41 行检查延时结束时是否仍高。
关键词与符号
调用形式与第 33 行相同，但所处阶段是断开/释放，不能把两个消抖阶段混为一谈。

为什么需要

删除或改错会怎样

通俗理解

课堂简答

第 41 行 · 释放后只复查一次高电平

它是什么，是什么意思
延时后 key 为 1 时，执行第 43、45 行计数和输出；若为 0，就跳过它们，退出本轮检测代码块，回主循环。

为什么需要

通俗理解

课堂简答
这句复查释放后的高电平，成立才加 1 并更新灯。若又是低，就跳过计数、回主循环；它不会在原地反复检查。

老师可能问：这个 if 不成立时会发生什么？

第 43 行 · 接通和释放确认后计数加 1

它是什么，是什么意思
只有接通确认和释放确认都通过才执行，使 count 增加 1。这是本程序唯一的脉冲计数加 1 位置。
关键词与符号
count 是 8 位无符号变量；++ 是自增。作为单独语句，其存储效果与 count=count+1 相同。
执行时单片机做什么
第一次有效动作把 count 从 0 改为 1；第二次从 1 改为 2。255 的下一次结果存回 unsigned char 为 0。此时 P1 在下一句之前还没有更新。
为什么需要
把已通过条件检查的一次完整接通与断开记录下来，而不是只读到低就计数。
删除或改错会怎样

通俗理解

课堂简答
count++ 把计数加 1。它只有在低电平和回高都通过消抖复查后才执行，255 后会回到 0。

老师可能问：count++ 在什么条件下执行？

第 45 行 · 取反输出新的二进制计数

P1 = ~count;
它是什么，是什么意思
将新 count 按位取反后的低 8 位送到 P1，让 count 中的 1 位对应低电平 LED 点亮。
关键词与符号
P1 是八位端口；~ 是逐位取反，把 0 变 1、1 变 0；= 将结果写到端口。由于 P1 只存 8 位，此处输出与 255-count 相同，count 本身不会被取反改写。
执行时单片机做什么
例如 count=5，即 00000101，P1 输出 11111010/0xFA；P1.0、P1.2 为低，这两个位的灯亮。
为什么需要
把内部数字变成可见显示，并匹配实验仪的“低电平点亮，灯亮表示数字位 1”逻辑。
删除或改错会怎样
删除后变量增加但 LED 保持旧显示。去掉 ~，亮的会是 count 的 0 位，显示反相，例如 5 的亮灯图案会表示 250。
通俗理解
逻辑计数的 1 要亮灯，就让对应 P1 输出变成 0。
课堂简答
这句把计数取反送到 P1。因为 LED 低电平点亮，count 的 1 位取反成输出 0，对应灯就亮。

老师可能问：P1=~count 为什么要取反？

if 复查失败的真实行为

第 39 行释放延时结束，如果第 41 行读到低，条件不成立，第 43 行和第 45 行都跳过，本轮 count、P1 不变，然后回到第 29 行主循环。这里没有另一个释放重试循环，不会在第 41 行原地一直等高。

下一轮从第 31 行重新读取当前电平；如果当时已经为低，该等待会直接跳过。后续是否最终计入一次，要看之后的实际高低波形。不能把“本轮跳过”说成“以后一定补计”，也不能无条件保证复杂长抖动只计一次。

本程序以常见机械抖动在实际消抖时间内结束为使用条件。若释放抖动跨过复查点，可能漏计；这是当前简化代码的行为，应在测试中记录。延时后读到高只证明该采样时刻为高，没有连续采样整个等待过程。

09 二进制与取反输出

从最低位到最高位，权值为 1、2、4、8、16、32、64、128。书写八位数字时采用 b7…b0，最右位 b0 对应 P1.0；实物灯的左右摆放不能代替接口位序核对。

例如 5=4+1，count 的 b2、b0 为 1；取反后 P1.2、P1.0 为 0，对应两灯亮。8 只有 b3 为 1，表示一盏权值 8 的灯亮，不是八盏灯亮。

灯亮表示 count 对应位为 1，同时该 P1 引脚输出 0。256 次后回到 0。灯按 b7…b0 排列；实物灯的位置以现场位序核对为准。

为什么与 255-count 相同

count 为 0～255 的八位无符号数，写入八位 P1 的取反结果与 255-count 相同，例如 5 对应 250/0xFA。最终代码保留的是 P1=~count;，减法只作为等价关系解释，不另给一份替换程序。

严格说，默认整数提升可能让 ~ 运算先在 int 宽度进行；写到 P1 后保留低 8 位。因此不能说 ~count 表达式无论何时都只算八位，也不能说它把 count 本身改了。

第 255 次有效计数八灯全亮；再一次，count 存回 unsigned char 为 0，P1=0xFF，八灯全灭。后续从 0、1、2…循环。

10 核心语句的课堂短回答

详细解释在前面的逐行卡片中。下面集中放最容易被老师指到的语句、通俗理解和 1～3 句口头答案。

第 7 行

void mDelay(unsigned char Delay)

通俗理解：把“循环等多少轮”交给调用时填入的数字。

口头回答
这行定义无返回值的延时函数，参数 Delay 用来控制外层循环次数。mDelay(20) 就把 20 传给它，但不自动保证是 20ms。

查看完整解释

第 11 行

for (; Delay > 0; Delay--)

通俗理解：还剩几轮就再做一轮，做完减一轮。

口头回答
这是外层延时循环。Delay 已由参数赋值，所以初始化部分留空；每完成一轮内层，Delay 减 1，变成 0 就结束。

查看完整解释

第 13 行

for (i = 0; i < 110; i++);

通俗理解：每一大轮，都从 0 重新数 110 次小循环。

口头回答
这个 for 让 i 从 0 增加到 110，执行 110 次。末尾分号是空循环体，循环判断和自增用于消耗 CPU 时间。

查看完整解释

第 23 行

key = 1;

通俗理解：先让引脚解除主动拉低，再读取开关的高低。

口头回答
P3 是准双向口，用作输入前先写 1，解除主动输出低电平，让外部开关控制实际输入电平。开关闭合时仍能读到 0。

查看完整解释

第 31 行

while (key == 1);

通俗理解：高的时候继续等，低了才做接通消抖。

口头回答
这句在输入为高时等待，第一次读到低就退出，进入接通消抖。末尾分号是有意的空循环体。

查看完整解释

第 35 行

if (key == 0)

通俗理解：等完还是低，才认可这次接通。

口头回答
这句复查消抖后的输入，仍是低才进入等待释放；如果已经高就不接受这次低电平，重新检测。

查看完整解释

第 41 行

if (key == 1)

通俗理解：最后再看一次，还是高就记一个，否则这轮先不记。

口头回答
这句复查释放后的高电平，成立才加 1 并更新灯。若又是低，就跳过计数、回主循环；它不会在原地反复检查。

第 43 行

count++;

通俗理解：这次接通又断开，两次确认都通过了，记一个。

口头回答
count++ 把计数加 1。它只有在低电平和回高都通过消抖复查后才执行，255 后会回到 0。

查看完整解释

第 45 行

P1 = ~count;

通俗理解：逻辑计数的 1 要亮灯，就让对应 P1 输出变成 0。

口头回答
这句把计数取反送到 P1。因为 LED 低电平点亮，count 的 1 位取反成输出 0，对应灯就亮。
