读代码时，先澄清这四件事
① 0x38 的 F=0，规范名称是 5×8 点阵字模。原注释“5×7”保留在源码里，讲解按规范说明。
② 原代码每次写入前都调用 fbusy()，但没有独立的上电唤醒流程。实物若未满足LCD内部复位条件，不能从第一步就假定BF可可靠读取；见模块二的初始化说明。
③ SP=0x50 是这份程序的固定设置。Keil启动代码通常已经安排堆栈，实物工程须核查内存分配，不能把0x50当作所有程序的通用初值。
④ 原代码未显式安排总线延时。能否满足时序取决于晶振、内核与编译后指令；本讲义的动画只解释逻辑，不代替Keil编译和Proteus验证。

Registers / distinguish MCU and LCD
02
先分清，两边的寄存器。
P1、P2、SP属于单片机；IR、DR、AC和BF属于LCD控制器。它们之间通过引脚与读写时序通信。
命令位图显示地址忙标志与时序硬件对应考前速记
单片机侧：P1.7/P1.6/P1.5输出RS/RW/E；P2承担8位数据双向传输；SP管理硬件堆栈。
LCD侧：IR接收指令，DR传递数据，AC保存当前地址，BF表示内部忙状态。DDRAM存字符编码，CGROM把字符编码转换成字模。
点选不同命令，再点击任一位；固定指令码位与可配置功能位会分别说明。RS、RW是独立引脚，不包含在P2发送的这个字节中。
Address / DDRAM is not the whole screen
0xC3，为什么是第2行第4列？
程序从0计行列；人阅读从1计行列。先算DDRAM地址，再加0x80组成定位命令。
点击小格选择起始位置。格子第一行是DDRAM地址，小字是人阅读的列号。
可见行（默认未移屏）DDRAM地址定位命令原程序起点
第1行0x00～0x0F0x80～0x8F(0,1) → 地址0x01，命令0x81
第2行0x40～0x4F0xC0～0xCF(1,3) → 地址0x43，命令0xC3
第16列之后会怎样？1602可见每行16字符，但控制器内部每行还有不可见地址。地址从0x0F继续递增到0x10，通常进入第1行不可见区域，不会直接跳到0x40。本程序没有越界检查或自动换行逻辑。
Bus / handshake before every write
先问“忙不忙”，再交出一个字节。
RS选寄存器类型，RW选方向，E划分读写周期。D7在状态读取中才表示BF。
RSRWLCD操作本程序对应
00写指令寄存器IRwc51r()
01读BF和AC：D7=BF，D6～D0=地址fbusy()
10写数据寄存器DRwc51ddr()
11读数据寄存器DR本程序未使用
写入：下降沿接收
fbusy();
E = 0; RS = 0; RW = 0; // 命令
E = 1;
P2 = j;
E = 0; // 在满足时序的下降沿接收
原程序先使E变高，再送j。关键是j在E下降沿前保持足够时间，下降沿后继续保持。更直观的写法可先放数据、再给E脉冲；都要依据实际时序。
读取：高电平期间采样
P2 = 0xFF; // 准双向口读前写1
RS = 0; RW = 1;
E = 0; E = 1;
while (P2 & 0x80) {
    E = 0; E = 1;
}
LCD在E高电平后需要数据有效时间。BF=1则重开一个读周期；BF=0退出。原函数返回时E仍为1，调用者下一条E=0结束读周期，再切换成写。
概念图不按真实时间比例。HD44780U在4.5～5.5V对应的总线表中，E高脉宽至少230ns、使能周期至少500ns、写数据建立至少80ns、读数据延迟最大160ns；其他电压和兼容芯片须查各自手册。不要用动画速度或C语句行数推算这些时间。
实物初始化：不能把BF检查当成上电等待的替代品
原init直接调用wc51r，而wc51r一开始就查BF。这依赖LCD已正确内部复位。若复位条件不满足，按HD44780U的8位初始化图：5V条件下，电源升至4.5V后等待大于15ms；发送无BF检查的0x30；等待大于4.1ms；再次0x30；等待大于100μs；第三次0x30；按图进入可检查BF的阶段，再配置功能、显示控制、清屏和输入模式。
这些早期写入不能再调用当前“一进门就fbusy”的wc51r。可另写无BF写命令函数，配合可靠延时；成功唤醒后再用正常忙检测。具体电源条件、等待和指令次序以实际模块手册为准。这里说明改进思路，没有悄悄替换原程序。
Hardware / mapping from this source
每个引脚，都能在代码里找到。
下表是由本份代码推导的接口关系；未提供本次Proteus原理图，不能据此断言你现有电路已经接对。
LCD常见引脚连接对象为什么这样接代码关联
1 / VSSGND，与单片机共地建立一致的电平参考。所有逻辑信号的电压基准
2 / VDD常见5V模块接+5V给控制器供电，按实际模块额定值。init之前必须先满足上电条件
3 / V0、VEE对比度电位器中点，另两端接电源与地调节字符与背景的对比度。背光亮但无字时应检查
4 / RSP1.7选择指令/状态或字符数据。sbit RS = P1^7;
5 / R/WP1.6既要写入，也要读BF。sbit RW = P1^6;
6 / EP1.5提供使能读写周期。sbit E = P1^5;
7～14 / D0～D7依次接P2.0～P2.7数据位权一一对应，D7还承担BF。P2=j；P2&0x80
15 / A、16 / K（如有）背光供电与回路依模块标识连接；是否需要外加限流电阻看模块规格。不由本程序控制
单片机还需要最小系统
AT89C51的电源、地、复位与时钟也必须正确。使用片内程序存储器时EA接高电平；在Proteus中需设置程序HEX与实际晶振频率。当前代码不能告诉我们晶振是多少，不能套用别的实验的频率。
读P2，为什么要先写1？
经典8051的P2是准双向口。写1使该位可作为输入，LCD才能输出BF与地址。P2=0xFF只是准备读总线；它不会自动发出一个LCD“显示全1”的指令。
本接法假定P2作普通I/O；若使用外部存储器总线，需要重新评估P2复用冲突。
Exam essentials / twelve anchors
答辩前，记住这十二件事。
16 × 2
两行，每行16个可见字符单元。
RS 0 / 1
0：指令或状态；1：字符数据。
RW 0 / 1
0：写；1：读，方向是相对于LCD。
E↓ 写入
满足建立、保持和脉宽后，在下降沿接收。
BF = D7
RS=0、RW=1时读取；1忙、0就绪。
P2 = 0xFF
经典8051准双向口读入前先写1。
0x38 / 0x0C
8位、两行、5×8；显示开、光标/闪烁关。
0x06 / 0x01
地址自增不移屏；清屏并地址归零。
0x80 + 地址
设置DDRAM地址命令的组成方式。
0x00 / 0x40
两行默认首地址；第2行不是0x10。
*str / str++
读取当前字符；移动到下一个字符。
strlen ≠ sizeof
前者不算\0；本数组sizeof则含\0。

在第2行第10列开始写OK。
展开参考修改与理由
先定义字符数组，再调用：
uchar msg[] = {"OK"};
lcd1602wstr(1, 9, strlen(msg), msg);
DDRAM地址0x49；定位命令0xC9。两字符落在第10、11列。
03 / 字符数量
只显示第二行文本的ARE。
展开参考修改与理由
显式指定发送3个字符：
lcd1602wstr(1, 3, 3, str1);
只写A、R、E。不发送后面的空格和YOU!。若原来已有旧字，需要额外覆盖。
04 / 指针
若删除str++，HOW会变成什么？
展开参考修改与理由
同一个地址被反复解引用，得到：
HHH
循环i仍会增加，LCD地址仍会自增，但源指针一直指向H。
05 / 光标
希望显示光标，并让光标位置闪烁。
展开参考修改与理由
把显示控制命令改为：
wc51r(0x0F);
D=C=B=1；文字显示、光标可见、光标位置闪烁。0x0E则光标可见但不闪烁。
06 / 旧字符
把ARE YOU!更新成OK，怎么避免尾巴残留？
展开参考修改与理由
从同一位置写足够长度，空格覆盖旧尾巴：
uchar msg[] = {"OK      "}; // 2字母+6空格
lcd1602wstr(1, 3, 8, msg);
原来8字符，新文本也覆盖8格。只写OK会留下原来的E YOU!。
07 / 循环
用while替代for发送字符。
展开参考修改与理由
保留定位语句，把循环改为：
i = 0;
while (i < length) {
    wc51ddr(*str);
    str++;
    i++;
}
i++与str++作用不同，两者都需保留。只增加指针、不增加i会无法正常结束。
08 / 接口
把RW固定接地，程序还要改哪里？
展开参考修改与理由
改为纯写方式后，应去掉读BF流程，改用满足手册的固定延时。
写命令/数据 → 固定等待 → 下次写
上电唤醒 → 独立可靠延时
不能保留当前fbusy。应按清屏/归位与普通命令分别满足等待，具体值看控制器与振荡频率。
一分钟讲清整个项目：单片机通过P2传送8位命令或字符码，通过P1的三根线RS、RW、E选择寄存器、方向并产生使能周期。初始化设定两行显示、地址递增并清屏；每次写入前读取D7忙标志，BF为0才继续。字符串函数先设置DDRAM起点，再用指针逐个取字符写入；最终HOW位于第1行第2列，ARE YOU!位于第2行第4列。静态内容写完后由LCD控制器维持显示。
