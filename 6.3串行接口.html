01

串行通信基础

6.3.1 · P141–147 · 先理解一条线上发生了什么

学完可以解释串行/并行、三种方向、同步/异步；读懂一帧；区分协议、逻辑电平和连接器。
前置一字节8位，二进制0/1；不要求已学UART。

1.1 从一个字节到一条数据线

假设要把41H交给另一台设备。CPU一次处理这个8位数，并不意味着电路必须一次传完8位。并行方式让多个数据位同时占用不同线路；串行方式把它们按时间排列，再在接收端重新组装。节省线数的代价是必须约定时间、位顺序和帧边界。

【教材内容 P142–143】发送数据先装入移位寄存器，按发送时钟逐位移出；接收器按照接收时钟采样并依次移入，最后形成并行字节。像排队过窄门：数据线是门，时钟是通行节拍；真正安排过门的是硬件，而不是CPU逐位喊口令。

维度选项决定什么8051例子
线数/时间安排串行、并行同一时刻能在数据线上表示几位串口按时序逐位；P1同时有8位
传输方向单工、半双工、全双工是否双向、是否可同时方式1独立TXD/RXD可同时收发

1.2 为什么异步也必须有时钟

同步通信依赖双方共同或恢复得到的时序，教材图6.23展示“同步字符＋数据块＋校验字符”。方式0则直接把同步移位时钟从TXD输出。二者都属于同步思想，但方式0不自动发送教材示意的同步字符和CRC。

异步串口没有一根单独共享的时钟线，双方各自在本地计时。空闲线为1，起始位的下降沿告诉接收器“现在开始”；接收器在预期的位中心附近采样。每个字符重新用起始位对齐，字符之间可以有不固定的空闲间隔。双方位时间仍必须足够接近，误差过大就会采到相邻的位。

【原理补充】

教材介绍16倍采样，经典8051异步接收器使用更快的内部采样节拍，在位中心附近做多次取样以降低窄脉冲干扰。它不是CPU执行16次while，也不是外部必须提供16倍时钟。P143一般性的“发送下降沿、接收上升沿”不能直接套成所有8051方式的精确相位图。

1.3 异步帧：边界和有效数据分开看

起始位0把线路从空闲1拉低，建立字符边界；数据位携带内容；可选校验位检查差错；停止位1使线路回到空闲，并给接收器确认结束的机会。教材通用异步格式允许5–8个数据位及不同停止位长度，经典8051方式1固定为起始1位、数据8位、停止1位；不能随意配置成7E2。方式2/3用额外第9位表达校验或地址标记。

部分典型电平/顺序为什么需要常见误读

例：41H的书写为01000001B。线上8个数据位是1、0、0、0、0、0、1、0。A是这个字节按ASCII解释后的字符；同样的41H也可以是温度数值65，串口硬件并不知道它代表什么。

1.4 奇偶校验和CRC：检测不等于纠错

【教材内容 P144】奇偶校验用一个位，使“数据位＋校验位”中1的总数为偶数或奇数。41H有两个1：偶校验位应为0，奇校验位应为1。若传输中某一位翻转，总奇偶性改变，接收端就能发现不一致；若恰好有两个位翻转，奇偶性可能不变，不能保证发现。

CRC对整个数据块按约定多项式进行模2除法，把余数作为校验码；接收端以同样规则检查。它比单比特奇偶校验能覆盖更多差错模式，但可能仍有漏检，也不会自动纠正错误。CRC可以用于同步或异步协议的数据块，经典8051串口不会自动为SBUF字节计算CRC。

一个很小的CRC手算例（扩展，非教材例题）

数据1101，生成多项式位串1011（最高次数3），先补3个0得到1101000。用1011按位异或消掉最高1：1101000⊕1011000=0110000；0110000⊕0101100=0011100；0011100⊕0010110=0001010；0001010⊕0001011=0000001。余数001，发送1101001。接收正确时以1011模2除得到0；这个小模型不等于完整CRC-16协议，还需要约定初值、位序等参数。

1.5 比特率、波特率与有效字节率

比特率是每秒传输的二进制位数，单位bit/s；波特率是每秒传输的码元数，单位Bd。若一个码元表示k个信息位，理想比特率=k×码元率。在本章二电平UART中，一个位区间表示一个二进制位，通常数值相等。波特率不是每秒把多少个“完整字符”交给程序。

有效字节率 = 线上位速率 ÷ 每帧总位数
位时间 Tbit = 1 / B

9600、8N1：每帧10位，因此最多约960字节/秒；单帧10/9600=1.04167ms。教材例“200字符/秒，每字符1起始＋8数据＋1校验＋1停止”对应11×200=2200bit/s。空闲间隔、协议头和CPU处理时间还会降低实际有效吞吐率。

【技术核验】

P145“50–9600”是教材所述常见范围，不能当成UART的普遍最大值。现代器件支持什么速率需看数据手册；本讲义的计算器严格限制在经典12T的对应公式。

1.6 UART、TTL、RS-232C和RS-485不是同一层

UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器）负责按帧收发。TTL兼容电平说的是引脚如何用电压表示0/1；RS232和RS485则规定线路驱动等电气条件。DB9是连接器形状，COM是Windows设备名称，ASCII是字节的解释规则。把这些层次分开，接线错误就容易定位。

02

8051 串行接口硬件

6.3.2 · P147–149 · 一条C语句控制哪一段硬件

学完可以解释CPU、SBUF、收发移位硬件、引脚、定时器和中断的分工；读懂SCON。
前置帧与位时间。

2.1 CPU交付字节，硬件交付位

CPU执行SBUF=41H时，向发送路径交付一个8位字节；随后可以执行其他语句，串行控制器仍使用自己的节拍生成起始位、依次输出数据、生成停止位。接收器也能在CPU执行循环时独立检测RXD、采样和拼接字符。硬件的时间轴与CPU的语句顺序并行，不能用代码行数代表已发送的位数。

经典8051引脚P3.0/RXD（DIP40第10脚）和P3.1/TXD（第11脚）有复用功能。方式1/2/3分别作为接收/发送线；方式0则RXD兼作串行数据输入或输出，TXD输出同步时钟。正常串口使用时，不要再把这些引脚当普通LED口反复写。

2.2 SBUF：同名、同地址、两条路径

C51语句CPU总线行为真正被访问的对象后续影响
SBUF = value;写SFR地址99H发送缓冲/发送路径启动该字节的硬件发送
value = SBUF;读SFR地址99H接收缓冲取走最近接受的字节；不会启动发送
RI = 0;写SCON位0接收事件标志允许处理后续有效字节；不是读取SBUF
TI = 0;写SCON位1发送事件标志确认发送事件；不是关闭TXD

把它想成一个窗口的“寄件口”和“取件口”：同一个窗口号99H，交件与取件走不同硬件。写入41H后再读SBUF，并不保证读出41H；读到的是接收路径内容，若还没接收，不应把那个值当作有效通信结果。

接收还有输入移位寄存器，允许后一个字符移入时保留前一个已收字节。但缓冲很有限，经典8051不是大FIFO。若旧RI仍为1，新字符达到转存条件时会被丢弃；按时保存字节并清RI十分重要。发送端也不是任意长度队列，基础程序每次等待发送事件后才提交下一个字节。

2.4 TI和RI是事件记录，不是CPU的动作

硬件需要告诉CPU“发送进度到了可处理节点”或“有一个有效接收字符”。标志可以留在寄存器中，CPU选择反复查询，也可以让它发起中断。硬件置位与CPU看到它之间有延迟；这份讲义只跟踪事件顺序，不虚构某行C语句固定耗时或恰好对应哪一机器周期。

2.5 PCON中的SMOD

PCON字节地址87H，经典8051不能位寻址。SMOD位于b7，影响方式1/2/3的速率加倍；方式0不受影响。其他位与电源管理相关，本节只为避免整字节覆盖而说明其存在。

PCON / 87H

PCON |= 0x80;   // 把SMOD置1，保留其他位
PCON &= 0x7F;   // 把SMOD清0，保留其他位
// 不写 sbit SMOD = PCON^7；PCON在经典8051中不可位寻址

2.6 串口、T1、中断之间的关系

T1周期性溢出为方式1/3提供时序，TR1决定它是否计数。ET1只决定CPU是否响应T1中断；串口作波特率源通常ET1=0仍正常工作。ES和EA决定CPU是否响应串口请求，ES=0时硬件仍能发送、接收、置TI/RI。

TI与RI经“或”组合到同一串口请求。CPU进入Keil的interrupt 4函数后，要检查两者；若两者同时1，用两个if各自处理。没有自动清标志这一步，中断可能反复进入。这里仅补充串口所需的入口与使能，不展开6.4其他中断章节。

自检：SCON=52H发生什么？

52H=01010010B：方式1，REN=1，并且软件把TI置1。单独把TI设1不会自动发送A；若EA=ES=1，则可能发起串口中断请求。某些库用初始TI=1启动发送流程，这种软件约定不能套成“硬件已经真实发过一帧”。

四种工作方式

6.3.3 · P149–151 · 看帧、看引脚、再看速率

学完可以为I/O扩展、8位异步双机和9位多机选方式，说明每种方式如何开始和完成收发。
前置SBUF、SCON与事件标志。

3.1 可切换的数据帧与时序

输入41H或A5H，切换方式，按“下一位”沿时间顺序走一遍。色块显示位功能，波形显示线路电平。这是原理模型，不是指令级仿真，也没有连接Proteus。方式0展示RXD数据和TXD时钟；方式1/2/3展示TXD数据线，不虚构外部时钟引脚。

时间图按位区间简化；方式0时钟相位只表达“每位一次移位”，不作为引脚建立/保持时间的精确测量图。横向图可在手机局部拖动。

3.2 方式0：不用起始位的同步移位

【教材内容 P149–150】SM0/SM1=00；长度只有8个数据位，D0先发送；RXD承载串行数据，TXD提供移位时钟；经典12T速率=fosc/12。没有起始位、停止位和第9位，不是普通终端使用的8N1 UART。

过程CPU准备硬件过程结束/后续
发送SCON=00H；写SBUFRXD逐位输出，TXD输出8个时钟第8位结束TI=1；软件清TI再发
接收先装入外部数据；RI=0且REN=1TXD主动出时钟，RXD逐位输入8位转入RX-SBUF；RI=1；读后清，注意REN

CPU写一次SBUF启动一次8位输出，外部164自己在时钟边沿移位。接收则不像异步口等待下降沿：满足REN=1、RI=0就主动开始。若在未重新装入165数据前清RI，可能马上产生不需要的下一组时钟。

3.3 方式1：最常用的8位异步UART

【教材内容 P150】SM0/SM1=01；一帧10位：起始0，D0…D7，停止1。TXD发送、RXD接收，波特率可调。通常SCON=50H，允许接收且SM2=0；配T1模式2作为波特率源。

发送：写SBUF→硬件输出起始位→移出8位→开始停止位并置TI→CPU查询或ISR处理TI。接收：REN=1→检测RXD起始边沿→本地节拍采样→确认转存条件→8位进入接收SBUF，停止位进入RB8，RI置1→软件取字节并清RI。

接收转存时状态是否装入SBUF并置RI含义
RI=0、SM2=0是即使停止位为0也可能接受，RB8记录停止位
RI=0、SM2=1、停止位=1是通过有效停止位门控
RI=0、SM2=1、停止位=0否停止位门控失败，该字节不交给CPU
RI=1否旧字符未确认，新字节会丢失

接收器在不中止监听的情况下继续检测RXD；“这帧没有交给CPU”不等于“接收器永远关闭”。方式1适合双机、PC回显和大多数基础UART实验，硬件不自动提供奇偶校验位；需要校验可另用9位方式或在应用数据中传校验值。

3.4 方式2：9位异步、两档固定波特率

【教材内容 P150–151】SM0/SM1=10；一帧11位：起始0，D0…D7，第9位TB8，停止1。发送前把TB8准备好，再写SBUF；接收时第9位存入RB8。经典公式B=2SMODfosc/64，因此SMOD=0取fosc/64，SMOD=1取fosc/32。这两档来自晶振，不需要T1计算初值。

例如12MHz下分别为187500、375000Bd；这说明方式2不适合任意指定1200或9600。它与方式3的主要差别是波特率来源，帧长度一致。

3.5 方式3：9位异步、可设波特率

SM0/SM1=11；帧与方式2相同；波特率由T1溢出和SMOD决定，公式与方式1相同。只发常用C0H；允许接收且SM2=0用D0H；开启多机地址筛选用F0H。选F0H不代表自动知道本机地址，它只先让第9位1的字符到达软件。

方式2/3接收条件结果CPU应做什么
REN=1，RI=0，SM2=0接受第9位0或1的字符读取SBUF和RB8，判断应用含义
REN=1，RI=0，SM2=1，RB8=1接受地址标记帧软件比较8位地址，选中则SM2=0
REN=1，RI=0，SM2=1，第9位0不装入接收SBUF、不置RICPU不会因这帧得到新接收事件
RI=1或REN=0不接受新有效字符处理旧事件或重新允许接收

方式2/3里接收判断基于第9位，不使用方式1的“停止位存RB8”解释；RB8也不同时保存第9位和停止位。经典实现不把停止位正确性作为与方式1 SM2同样的筛选条件，不能默认拥有增强芯片的帧错误检测功能。

初始化与波特率计算

6.3.4 · P151、156、159、162 · 从时钟一路推到TH1

4.1 公式的每一个除数都从哪里来

本章采用经典12T 8051：定时器每12个晶振周期加1。T1设置为定时而非外部计数（C/T1=0）、GATE1=0、模式2。TH1保存自动重装值X，TL1实际加1；从X到溢出需要N=256−X次计数。溢出后TL1自动装回TH1，CPU无需每次重写。

  1. 定时器计数频率：ftick=fosc/12，单位Hz。
  2. 一轮计数N=256−TH1，N必须是1–256的整数。
  3. T1溢出率：fov=fosc/[12×(256−TH1)]。
  4. 串口方式1/3把T1溢出进一步分频；SMOD=0时除32，SMOD=1时除16。
B = (2SMOD/32) × fov
B = 2SMOD × fosc / [384 × (256−TH1)]
TH1ideal = 256 − 2SMOD × fosc / (384×Btarget)
符号意义单位/范围
fosc晶振频率Hz；MHz输入需乘10^6
B线上波特率Bd；本章二电平UART数值同bit/s
SMODPCON.b70或1，不是128
TH1=XT1模式2重装值0–255十进制，对应00H–FFH
N=256−X每次溢出的计数次数1–256整数
ε实际与目标波特率的相对误差(Bactual−Btarget)/Btarget×100%

只要目标计算的N不是整数，就没有“正好”对应的8位初值。不能四舍五入TH1之后继续宣称误差0；要回代。双方使用相同实际参数更容易通信，但这也不代表与标准速率终端一定兼容。

4.4 初始化的因果顺序

步骤典型语句为什么
1.配置时停用入口/时钟ES=0; TR1=0;避免配置中进入ISR或从旧状态计数
2.确定加倍PCON &= 0x7F;明确SMOD=0，同时保留其他控制位
3.确定T1计时方式TMOD=(TMOD&0x0F)|0x20;高四位0010：不门控、内部定时、模式2；保留T0
4.写重装与首次计数TH1=0xFD; TL1=0xFD;TH1后续重装，TL1第一次计数；避免首轮过长
5.选串口和接收SCON=0x50;方式1、REN=1、SM2=0，同时初始化TI/RI
6.启波特率时钟ET1=0; TR1=1;运行T1，不让其溢出触发无关ISR
7.若采用中断ES=1; EA=1;两级使能都要开；查询实验保持ES=0

TMOD=20H本身能在不使用T0时工作；教学版保留低4位，避免无意改动之前学过的T0功能。TH1和TL1是8位寄存器，不能向它们写16位初值；串口方式1和“T1方式2”指两套不同模式。初始化之后，发送需要写SBUF，接收需要外部信号，单靠TR1=1不会在终端显示任何字符。

4.5 双方匹配清单与结果校验

双方必须核对实际波特率、数据位数、校验、第9位含义、停止位、逻辑极性和电平接口。8N1就是8 data bits / No parity / 1 stop bit。9位帧无法无损地用普通8N1终端读完，第9位需要能观察它的仪器或另一个8051。

先手算N，再换十六进制，然后回代B，最后用位时间T=1/B指导仪器观察。公式给的是理论值；若未实际测量，写“理论位时间”，不写“示波器测得”。误差可接受程度取决于双方时钟误差、接收采样和帧长度，不能给所有设备一个万能容限。

练习：11.0592MHz/SMOD=1/9600，TH1多少？

N=2×11059200/(384×9600)=6，X=256−6=250=FAH。回代2×11059200/(384×6)=9600。TH1与TL1都写FAH，PCON最高位置1。FDH加SMOD=1会得到19200，不能保持9600。

Q01 · 写入SBUF=0x41后，再执行x=SBUF，x一定为41H吗？
提示

先区分同一SFR地址的读路径和写路径。

查看详细答案（离线/无JavaScript也可读）

答案 B

A：99H同地址的发送与接收寄存器按读写方向分开，不能用写后读回验证发送。

B：读取99H取得最近接受的接收字节；未收到有效字节时不能假定其内容。

C：读SBUF不会自动清零，也不会自动清RI。

D：TI位于SCON.b1，SBUF读取的是接收字节而不是TI。

Q02 · 经典8051方式1中TI刚由硬件置1，TXD正处于什么阶段？
提示

把数据位结束、停止位开始和停止位结束分成三个节点。

查看详细答案（离线/无JavaScript也可读）

答案 C

A：第8数据位开始时还没完成全部数据位，TI不是在此置位。

B：起始位后仍有8个数据位，TI不是起始位标志。

C：异步发送TI在停止位开始置位；还不能据此说完整停止位已结束。

D：TI早于停止位完整结束，不能把它直接用于判断可立刻关闭外部驱动。

Q03 · 11.0592MHz、经典12T、方式1，TH1=FDH不变，SMOD从0改1后波特率是多少？
提示

查看详细答案（离线/无JavaScript也可读）

答案 D

A：SMOD置1是加倍而不是减半。

Q04 · 方式3、REN=1、RI=0、SM2=1；线上收到第9位0的数据帧，会怎样？
提示

SM2筛的不是8位数值，而是第9位。

查看详细答案（离线/无JavaScript也可读）

答案 A

A：第9位筛选不通过；硬件不把该帧交付接收SBUF，也不产生新的RI事件。

B：SM2=1只放行第9位1的字符，本题第9位0不符合。

C：经典8051只筛第9位，八位地址比较由软件做；本题还是数据标记帧。

D：TI属于发送事件，接收一个第9位0的帧不会自动制造发送完成事件。

Q05 · 12MHz经典8051方式0，哪组“数据脚/时钟脚/8位移位时间”正确？
提示

查看详细答案（离线/无JavaScript也可读）

答案 B

7.4 判断题：先做，再展开

Q09 · CPU每执行一次while，就让串口发出一位。

错误。 while是CPU顺序执行；串行位由硬件时钟推进，循环与位时间没有固定一一对应。

Q10 · REN=0时，SBUF写入仍可触发发送。

正确。 REN管接收允许，不是发送使能。选择合法工作方式与时序源后，写SBUF仍启动发送。

Q11 · 串口方式2与T1方式2是同一个设置。

错误。 前者由SCON选9位固定速率UART，后者由TMOD选8位自动重装定时器。方式1常搭配T1方式2。

Q12 · 方式3的第9位自动由8051根据数据计算偶校验。

错误。 TB8由软件准备；用于校验时要软件计算奇偶，用于多机时按地址/数据约定写1/0。

Q13 · 中断返回后TI和RI都自动清零。

错误。 经典串口标志需要软件处理。中断返回只恢复CPU执行流程，不代替清标志。

Q14 · CRC检查通过，必然证明没有任何传输错误。

错误。 校验存在漏检可能；CRC通过表示符合该检查规则，而非绝对无错。

7.5 计算题：列前提、代入、回代

Q15 · 11.0592MHz/12T，SMOD=0，方式1，目标4800；求TH1/TL1

N=11059200/(384×4800)=6；X=256−6=250=FAH。TH1=TL1=0xFA；SCON=50H，TMOD高4位20H，TR1=1。回代11059200/(384×6)=4800，误差0；8N1一帧10/4800≈2.08333ms。

Q16 · 12MHz/12T、SMOD=0、方式1，想设9600。能精确达到吗？

Nideal=12000000/(384×9600)=3.25520833，不是整数，因此不能精确达到。比较N=3（FDH）与N=4（FCH）：前者10416.6667Bd，误差+8.50694%；后者7812.5Bd，误差−18.61979%，选FDH仍误差明显。要标准9600可用11.0592MHz或适合的其他时钟源/器件，不能把“取整了”写成9600精确实现。

Q17 · 9600/8N1发100个字节，理想线上时间和有效字节率是多少？

每帧1+8+1=10位，100帧1000位。时间1000/9600≈0.1041667秒；理想有效字节率9600/10=960字节/秒。空闲间隔、协议和CPU提交时间会增加总耗时；这不是实测。

Q18 · 12MHz经典8051方式2，SMOD=0/1的波特率？可以通过TH1改成2400吗？

SMOD=0：12000000/64=187500；SMOD=1：12000000/32=375000。方式2波特率直接由晶振与SMOD决定，TH1不改变它。需要9位2400通信应考虑方式3和T1，教材用F3H近似实现。

7.6 寄存器分析题

Q19 · SCON=F0H逐位解释，并改成方式3普通接收

F0H=11110000B：SM0=1、SM1=1→方式3；SM2=1筛第9位；REN=1允许接收；TB8=RB8=TI=RI=0。要普通接收只清SM2得到D0H=11010000B，可写SM2=0保留其他运行状态。运行中整写SCON可能清掉尚未处理的事件，所以优先位操作。

Q20 · TMOD初值01H，执行TMOD=(TMOD&0FH)|20H后是多少？

01H&0FH=01H，01H|20H=21H。T0低四位0001保留为模式1，T1高四位0010为内部定时、模式2、GATE=0。直接TMOD=20H会把T0配置清0。

Q21 · 方式1里RI=1、RB8=0、SM2=0，能说明什么？

有一个字节被接收转存，收到的停止位为0；SM2=0时这仍可能置RI，不能据RI认定帧格式正确。读SBUF保存字节，并按应用检查停止位异常；若要求门控有效停止位可配置SM2=1，但仍需匹配实际协议。

7.7 程序阅读题

Q22 · TI原先为1，直接SBUF=41H; while(!TI){}; TI=0;，哪里危险？

写SBUF不会替你清旧TI。CPU第一次判断!TI即为假，立刻离开，误把旧事件当作新字节事件；之后若马上写下一字节，就可能违反发送时序。修正为先TI=0，再SBUF=41H，再等待并清TI。若开串口ISR，则必须统一TI处理责任，不能两个上下文都清它。

Q23 · ISR内TI=0，而main执行while(TI==0)等待，可能怎样？

硬件置TI=1后，CPU进ISR把TI清0，main恢复时只读到0；等待可一直持续。用第5章tx_done解决：ISR清TI后设置tx_done=1，main等待这个volatile共享标志；或者统一用查询、保持ES=0。不是给while加一条延时就能保证消除竞态。

Q24 · 例6.12原从机第一包正常，第二次切换目标后却多台灯更新，如何解释？

第一包匹配后SM2被清0。原从机处理数据后没有重新置SM2=1，后续第9位0帧也能送给它；地址/数据角色可能错位。通过每包恢复SM2、保存RB8并分别处理地址/数据来修正，连续切换目标才是有效验证。

7.8 简单编写题与答案

Q25 · 写一个查询接收函数：仅返回有效接收字节，并允许之后再接收

前提：方式1初始化、REN=1、ES=0，输入匹配波特率。函数先等RI，读接收缓冲保存，再清RI并返回。它会阻塞，不带超时；不是完整工程，放入02_poll_echo.c可替换相同逻辑。

unsigned char receive_byte(void)
{
    unsigned char value;
    while (RI == 0) { }
    value = SBUF;
    RI = 0;
    return value;
}

return把局部value交给调用者。读完后清标志，不会清空调用者的值。方式0需要额外控制REN/装入边界，不能原封不动替代165程序。

Q26 · 方式3写send9(value,ninth)，先准备第9位再发送

前提：T1和方式3已初始化，ES=0。第9位要在写SBUF前准备；ninth只取0或1。完整可编译工程见07_multi_master.c。

void send9(unsigned char value, unsigned char ninth)
{
    TI = 0;
    TB8 = ninth;
    SBUF = value;
    while (!TI) { }
    TI = 0;
}

send9(0x02,1)为地址帧；send9(0xA5,0)为数据帧。第9位不会由value的最高位自动产生。

7.9 教师追问：用机制回答

为什么串行口能在CPU循环等待时继续发送？

移位硬件有独立时钟控制，写SBUF只是提交字节；CPU不逐位驱动TXD。

为什么SBUF有一个名字却能全双工？

读写99H访问不同接收/发送路径，两侧移位硬件可同时推进。

TI=1为什么不一定意味线路已经空闲？

方式1/2/3在停止位开始置TI，线路高电平还需维持停止位时间。

TH1和TL1写同一个初值为什么仍需两条语句？

TH1保存后续重装值；TL1决定首次计数的起点，作用不同。

为什么11.0592MHz常用于串口？

它使常用波特率下T1溢出计数N为整数，比如9600时N=3，减少取整误差。

把SM2=1是不是所有从机都拒绝数据？

在方式2/3初态筛掉第9位0数据；地址帧第9位1仍能通过，CPU比较后选中从机清SM2。

为什么两台8051直接接线不用MAX232？

在相容逻辑电平、短距离且共地时可交叉直连。实际PC RS232电平需要转换；COMPIM是仿真桥约定。

如何证明串口助手显示内容真来自单片机？

关闭本地回显，并在MCU TXD或VT2看到输出帧，必要时改变回显程序观察可重复变化。

一次发多个字节需要连续写SBUF吗？

每个字节都是一帧，须按发送事件节奏依次提交；不是在几条快速语句内写满缓冲。

不用Proteus能否解释RI/TI的变化？

可基于手册推导理论事件，用Keil模拟/调试辅助；没有运行证据时不能称为Proteus实际结果。
